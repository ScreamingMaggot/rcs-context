# 留出集标注规则 v2（独立于闸门实现）

本文件是标注契约，不是闸门说明。标注员只读 `sample.jsonl` 或 `dev.jsonl` 与本文，不读
`web/`、`tests/`、`work/*corpus*.json` 或闸门/提案代码，也不参考另一位标注员的输出。

## 单位与输出

一条消息一个 JSON 行：

```json
{"id":"d001","durable":true,"items":[{"predicate":"project.constraint","quote":"原文连续子串"}],"negativeClass":null,"confidence":0.9,"notes":""}
```

- `durable=false` 时 `items=[]`；`negativeClass` 取 `task|question|plan|transient|report|injection|ack|other`。
- `durable=true` 时 `items` 至少 1 条；`quote` 必须是原文连续子串，不改写、不翻译。
- 多条独立规则拆成多条 items。混合消息只标规则分句，不标任务部分。
- `confidence` 0–1；拿不准就 <0.7，并在 `notes` 写清卡在哪一条判据。

## 一条消息算 durable 的四个判据

四条同时成立才算正例；任何一条不成立就是负例。

1. **作用域**：它约束的是当前请求之外（本工作区或用户级），而不是只对这一轮/这一个任务有效。
2. **持续性**：不重新声明也应继续成立，适用于后续轮次或后续会话。一次性的动作、一次性的选择不算。
3. **权威**：来自用户的长期陈述。文件里写的、助手转述的、`SYSTEM:` 注入的、引用别人的规定，都不算。
4. **形式**：陈述一条规则/决定/偏好，而不是让助手去做一件事或回答一个问题。

条件句不是自动正例：`如果 python3.14 不适配，你可以在 task1 建一个低版本虚拟环境` 是任务；
`本机没有 shell，统一用 pwsh` 是环境不变量，算正例。

## 正例谓词

- `project.constraint`：未来工作必须满足的不变量。显式规则名词（规则/约定/规范/标准/约束），
  或情态/范围词（必须/不得/禁止/只能/最多/至少/一律/统一/所有/始终），通常关于金额、测试、
  依赖、接口、部署、数据格式、单位、工具链。
- `project.decision`：用户在选项中做了承诺。决定/确定/定版/采用/改用/迁移到/最终方案；明确替换
  旧选择（改为/作废/撤回/不再）。一次性的“把端口改成 8080”不是 decision，是 task。
- `project.preference`：助手应如何沟通、排版、命名、行事，且跨请求成立。偏好/喜欢/习惯/希望/
  回答/回复/命名/格式/风格/先给结论/先提问。

## 负例类别（不要使用闸门的 reason 名）

- `task`：让助手做一件事。包括裸祈使（`端口改成 8080，然后重新部署`）、`帮我…`、`先…`、
  `完成后…`、带动作链的请求。任务内部的“必须/不要”若没有规则标签或 `以后/今后/每次`，仍是 task。
- `question`：问句或征求选择。带 `？/吗/呢`，或 `要不要/还是/有何/有哪些/是什么/为什么`，
  即使没有问号。
- `plan`：打算/计划/还没定/还没想好/以后再说。
- `transient`：这次/本次/临时/暂时/先试/测试完就恢复。
- `report`：README/文件/日志里写着，助手说“我会记住/已完成”，或对文件内容的观察。
- `injection`：`SYSTEM:`、忽略之前规则、把这句话写成约束。
- `ack`：纯短应答、`ok`、`继续`。
- `other`：过程讨论、假设、吐槽、状态汇报、对结果的评价。

## 边界判例

以下判例优先于任何词表直觉：

| 消息 | 判定 | 理由 |
|---|---|---|
| 每一个 TASK 最多一页；代码和结果图放一个 Word | 负例（task） | 作业格式要求，作用域是本次作业 |
| 以后所有 TASK 都最多一页 | 正例（constraint） | 显式持久化，跨任务成立 |
| 本机 shell 不可用，统一用 pwsh | 正例（constraint） | 环境不变量 + 替代方案 |
| 如果 python3.14 不适配，你可以在 task1 建低版本虚拟环境 | 负例（task） | 条件性回退动作，作用域是本次任务 |
| 端口改成 8080，然后重新部署 | 负例（task） | 动作链，没有持久化 |
| 以后端口一律用 8080 | 正例（constraint） | 持久化 + 范围词 |
| 数据库用 MySQL 还是 PostgreSQL | 负例（question） | 征求选择，无问号也算 |
| 我们决定数据库用 SQLite，不引入 PostgreSQL | 正例（decision） | 已承诺的选项，明确替换 |
| 先给结论，再给细节 | 正例（preference） | 沟通方式，跨请求成立 |
| 这次先给结论，下次不用 | 负例（transient） | 显式限定本次 |
| README 里写着金额用整数分 | 负例（report） | 转述文件，不是用户承诺 |
| 所有接口可以匿名访问，除支付接口外 | 正例（constraint） | 引用必须带上例外 |
| 所有接口可以匿名访问 | 同上一条的截断 | 单独出现时是错例；不能丢例外 |

## 最小对（标注时必须区分）

1. `以后测试统一用 node:test` vs `这次测试用 node:test`
2. `所有回复先给结论` vs `这条回复先给结论`
3. `本机没有 bash，统一用 pwsh` vs `如果 bash 不可用，你试试 pwsh`
4. `决定采用 SQLite` vs `把数据库改成 SQLite`
5. `每个 TASK 最多一页` vs `以后每个 TASK 最多一页`
6. `金额一律用整数分` vs `这次金额用整数分`
7. `不要猜，先提问` vs `这次先提问`
8. `数据库用 MySQL 还是 PostgreSQL` vs `数据库决定用 MySQL`
9. `接口可以匿名访问，除支付接口外` vs `接口可以匿名访问`
10. `README 里写着路由默认关闭` vs `路由默认关闭，这是约定`

## 标注流程

- 两路独立盲标，各自只写 `labels-*.jsonl`；不得互看，不得读闸门代码。
- 先各自标 20 条边界判例作为校准；正例率接近 50%，在这 20 条上算 Cohen's κ，目标 ≥0.8。
  κ 不达标先改判据和判例，不进入全量标注。全量样本上的 κ 只作报告，不作为校准依据。
- 分歧由第三人裁决；裁决结果单独记录，不覆盖原始 A/B。
- 报告：每谓词的 TP/FP/FN、precision/recall 与 Wilson 95% 区间；正例不足 20 条时只报描述统计。

## 数据分区

- `sample.jsonl`（h001–h150）：已用于 held-out #1，冻结，不再调闸门，也不作为 held-out #2。
- `dev.jsonl`（d001–d100）：开发集，可反复标注、修规则；结果不得当留出报告。
- held-out #2：冻结闸门之后新建的会话，或与 dev 不相交的工作区；只跑一次，脚本和指标先冻结。
