RCS 0.1.28 改进与保留项
================================================================================
插件版本：CONTEXTinjector v1.10.33（折叠账本幂等 + monotonic 实算 + 空 sid 回退 + 计量口径两处修正）
上一版：0.1.27（压缩比口径修正：本折 appended / incrementalRaw）
回退点：rcs-0.1.28 → rcs-0.1.27 → rcs-0.1.26 → … → rcs-0.1.8

发现的路径：2026-10-09 在 DSH 0.2.0-rc.2 上做**真实运行时验收**（隔离 DSH_HOME、仓库副本插件、
四轮续接会话）时，验收判定器报出「同一笔折叠被写两行」。逐条复核后定位到两个账本问题与一个
文件名边界问题。三处都不影响"模型看到的内容"，但都影响**账本可信度**，故单出一版。

--------------------------------------------------------------------------------
一、折叠账本幂等：同一区间不再重复记账（重要度：高）
--------------------------------------------------------------------------------
症状：fold-index 里每笔折叠各出现**两行**，除时间戳外逐字相同，间隔 1.7–1.9 s。
      两个独立会话复现（7 行 / 4 个 foldSeq；5 行 / 3 个）。
根因：`scheduleFold` 有两个独立触发点 —— `agent/turn-stopping`（contextinjector.mjs:2172）
      与 `turn/end` 兜底（:2233）。两者会对**同一区间**各提交一次折叠；
      `enterFoldInflight / joinFoldInflight` 只保证"不并发"，不保证"第二次发现这段已折过就跳过记账"。
影响：任何**按行求和**的总账（raw / appended / 压缩倍数）都会翻倍。
      已核：真实会话 5fe3512e 的账本干净（6 行 6 个 seq，1,544,906 → 304,010 B = 5.08×），
      ⇒ 课堂 deck 与论文引用的数字**未受影响**；但 0.2 上的新会话会中招。
修法：`writeFoldIndex` 写前比对**本会话最后一行**的 foldSeq，相同即视为同一笔，跳过记账。

--------------------------------------------------------------------------------
二、monotonic 由硬编码 true 改为实算（重要度：中）
--------------------------------------------------------------------------------
症状：fold-index 每行的 `monotonic: true` 是写死的常量（contextinjector.mjs 旧实现），不是测量值。
影响：这是"自证字段"——下游会把"机器没验过"当成"已验证"，与 22.4× 那次的教训同类。
修法：按 (a) 遮蔽 seq 严格递增、(b) cumLines.after ≥ cumLines.before 两项实算；
      缺 cumLines 时只按 seq 判（保守 true，但不再无条件 true）。

--------------------------------------------------------------------------------
三、sanitizeSid 空串回退 unknown（重要度：中）
--------------------------------------------------------------------------------
症状：旧实现 `String(s ?? 'unknown')` 对**空字符串**仍得 ''，于是 fold-index / last-fold / raw 的
      文件名叫 `.jsonl` / `.json` —— 同一目录下所有「sid 为空」的会话**共用同名文件**，账本互相混写。
      sid 来自 sessionIdOf() 的 id/sessionId/goalId/name，缺失链路上任一处忘了守卫就会走到这里。
修法：`String(s ?? '').replace(...).slice(0,120) || 'unknown'`。null/undefined/纯空白/纯符号一律有名字。

--------------------------------------------------------------------------------
四、转录轮转段的轮号续传：只扫 4 个段文件 ⇒ 重启后轮号重复（重要度：高）
--------------------------------------------------------------------------------
症状：对长会话（转录超过 ROTATE_BYTES 会轮转成 <file>.1 / .2 / …）做**跨进程续写**时，
      新轮拿到的 [ROUND] 号偏小 ⇒ 与既有轮号**重复**。
      实测（8 轮 / 轮转出 5 段：base + .1…​.4）：重启后新一句仍写 `[ROUND] 8`，应为 9。
根因：`lastRoundInDir()` 写死扫 `[base, base.1, base.2, base.3]` 四个文件，而轮转段编号**无上限**；
      最大轮号恰好落在 .4 段里 ⇒ 扫不到 ⇒ 续号从偏小的值起。
影响：转录的轮号是**审计口径**（"每轮"是 deck/论文所有读数的时间轴），重复轮号会让"按轮聚合"出错。
      不影响模型看到的内容（折叠按 seq，不按轮号），故不影响压缩与计费读数。
修法：改为**枚举目录**取全部匹配段（`<key>.log` 与 `<key>.log.<n>`），再取最大 [ROUND]。
交叉印证：WebUI 的转录导出早已是动态拼接（`contextinjector-webui/lib/index.mjs`：按 .log.1 … .log.<maxN>
      + 当前段），两处口径现在一致。
回归：新增 `tests/transcript-rotation-resume.test.mjs`（14 条）——轮转不丢行、轮号跨段连续、
      换模块实例（模拟宿主重启）后续号 = 各段最大值 + 1、旧段一字不动。

--------------------------------------------------------------------------------
五、计量口径两处修正（重要度：中）
--------------------------------------------------------------------------------
症状（两份都由端到端桩测暴露）：
· `applyCondense(rows, 'off', io)` **在 off 档下真的会调模型**：函数内部没有 off 分支，只靠调用方
  `if (mode !== 'off')` 防护。线上安全（唯一调用点有守卫），但这是 latent footgun——任何新调用点
  漏判就会在"无损档"照样花钱、照样改行（实测确认：真发起调用、真替换 [A]）。
· `last-fold.calls` 把**未真正发出的调用**也计了：`foldCalls += 1` 是"预算预约"，而短行（minBytes）
  与回本闸（payback）会在 condenseText 内部**提前返回**、一次请求都没发。实测 tooShort 行 `calls=1`
  而 `auxCalls=0`。K 通道此前已单独修过同类问题（keysSkippedBudget），单通道漏了。
修法：
· off 档契约下沉到函数内部：`applyCondense` 开头 `if (mode === 'off')` 直接原样返回（并给出同形的
  stat：calls/callsReserved/ms/budgetHit 全为 0/false，避免下游读到 undefined）。
· `calls` 改为**真实发起的请求数**：在 `llmText` 里（过了 llm/route 两道守卫之后）`io.attempts++`；
  `applyCondense` 用差值写入 `stat.calls`，预算预约数另存 `stat.callsReserved`（新增诊断字段，
  旧消费方零改动）。含随后失败的调用——"钱花了就要记"，与 usage 计量同精神。

六、验收
--------------------------------------------------------------------------------
离线回归：**16 套 / 394 条断言全绿**（`node tests/run-all.mjs`，0.9 s）。新增 7 套：
· `fold-index-idempotent.test.mjs`（13）——同一 foldSeq 只记一次；换笔正常追加；总账"全行求和 == 去重求和"；
  monotonic 实算的三种形态（正常 / seq 回退 / cumLines 回退）；不同 sid 互不干扰。
· `condense-classification.test.mjs`（34）——来源分型七类 + 双形态 plugin id；只用 kind==='user' 判真人轮；
  classifyUserMessage 读 data.source（旧取 data.message.source 恒 undefined）；失败分型枚举；里程碑三门槛；
  分块"不丢字符"与"硬切不越界"；预算"先保底再封顶 + 留 20% 余量"。
· `payback-and-budget.test.mjs`（20）——回本回合数 = 成本 ÷ 每回合收益，随正文变大**严格递减**；
  收益为 0 ⇒ Infinity（不 NaN）；实测回本无 usage ⇒ null；成本按账单口径 in + cacheRead×0.25 + out。
· `sid-sanitize.test.mjs`（37）——12 类敌意 sid 的落点全部仍在本目录内、幂等、截断 120、
  空串回退 unknown；rawAppend 真追加且不越界。
· `toolfold-value-retention.test.mjs`（28）——命令/路径/模式逐字保留；size/lines/sha8 取自真实字节；
  错误首行同时进 [T] 与 [V] 并带 ref=Vn；[V] 转义**可逆**（含 | " \ CRLF）；长输出标 tee=REQUIRED。
· `transcript-rotation-resume.test.mjs`（14）——轮转（base → .1）不丢行、轮号跨段连续；
  **换模块实例 = 模拟宿主重启**后轮号从"各段最大值 + 1"续上（不归零）；旧段一字不动。
· `condense-pipeline.test.mjs`（22）——**端到端**跑浓缩流水线（桩掉 llm：`io.llm.stream` 吐
  text-delta/usage/finish）：off 档零调用零费用；值保真第一道防线（模型收到的文本里**没有原值**、
  只看到占位符；回吐占位符后逐字回填出原值）；四类回退分型（noShrink/empty/llmErr/流异常）都无损；
  截断走"抢救成功"（salvaged）而非回退，且留半截占位符时抢救闸拦住；短行与回本闸在**花钱之前**
  拦住（calls 计为 0、预约数另记）；payloadCheck 默认关/显式开拦住改值；double 档 K 通道只收
  "整词出现在原文"的关键值、幻觉值被剔。

真机验收（DSH 0.2.0-rc.2，隔离 DSH_HOME，`迁移/_rcs-accept/`）：
