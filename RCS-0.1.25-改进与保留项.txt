RCS 0.1.25 改进与保留项
================================================================================
插件版本：CONTEXTinjector v1.10.29 / EXTREASON v0.3 M2 / LOGcompiler v3 / toolfold（含单行契约修复）
上一版：0.1.24（toolfold 单行契约）
回退点：rcs-0.1.25 → rcs-0.1.24 → rcs-0.1.23 → … → rcs-0.1.8

本版主题：**目录重构 —— 让 RCS 成为一个可被 `dsh plugin add` 直接安装的插件包**


--------------------------------------------------------------------------------
一、为什么重构
--------------------------------------------------------------------------------
此前 GitHub 仓库是"下载 zip + 跑 install.ps1"的分发形态：仓库根平铺着四个 .mjs，
install.ps1 把它们铺到 DSH_HOME/profiles/{web,condense,toolfold} 三个子目录，
再往 cordis.patch.yml 里插四条 insert。

实测（2026-09-30）：
    pnpm add github:ScreamingMaggot/rcs-context   → 解析成功、文件落地，但 pnpm 写出
    {"_pnpmPlaceholder":"This file was generated by pnpm. The original package did not
    contain a package.json."} ⇒ cordis 拿不到 name/main/bundle 声明 ⇒ 装了不加载。

而 DSH 侧并不存在"市场探测"：0.2.0-rc.2 全树无 marketplace/pluginCatalog/browsePlugins；
`dsh plugin --profile <name>` 是 **pnpm 透传**，发现方式只有"用户自己填安装规格"。
所以"能被安装"= "仓库本身是一个合法的插件包"。


--------------------------------------------------------------------------------
二、包形态的契约（全部实测得出）
--------------------------------------------------------------------------------
1. `package.json` 声明 `"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }`；
   dsh 侧原文：`dsh: warning: <name> declares no dsh.bundle — installed as a plain
   dependency, not a profile layer`。bundle 就是"包自带的补丁层"。
2. 包内 `cordis.patch.yml` 用**包内相对路径**引用插件：`name: './web/contextinjector.mjs'`。
3. **目录布局必须是 `web/ + condense/ + toolfold/`** —— 因为插件源码里写的是
   `../condense/chunk.mjs`、`../toolfold/toolfold.mjs`。这个布局与装进 DSH_HOME 后的
   profile 布局同构，于是**两种装法共用同一份源码，零分叉**。
4. 装完后该包**必须被选进 profile 的 `dsh.profile.bundles`**，否则装了也不加载
   （`dsh plugin add` 不自动激活）。

踩过的坑（均已在隔离 home 复现并解决）：
   · `files` 白名单漏 `cordis.patch.yml` ⇒ 装进去的包里没有补丁层；
   · 嵌套 `file:` 依赖 ⇒ tarball 安装报 ERR_PNPM_LINKED_PKG_DIR_NOT_FOUND；
   · 目录式 `file:` 安装会丢文件（改用打包后的 tgz / git 规格）；
   · `git+file://C:/...` 被 pnpm 解析成 `file://C/...`（盘符冒号丢失）⇒ 必须写
     `git+file:///C:/...`（三段斜杠）。


--------------------------------------------------------------------------------
三、本版改了什么
--------------------------------------------------------------------------------
· 仓库结构：contextinjector.mjs / logcompiler.mjs / extreason.mjs → `web/`；
  toolfold.mjs → `toolfold/`；condense/ 与 contextinjector-webui/ 不变。
  使用 `git mv`，历史保留。
· 新增根 `package.json`（name=rcs-context，version=0.1.25，type=module，
  files/exports/dsh.bundle）与根 `cordis.patch.yml`（四条 insert）。
· `install.ps1` 的**源路径**随之更新（web\… / toolfold\…）；落位路径与备份/回滚逻辑一字未动。
· 两个测试的夹具源路径同步更新。
· README「兼容性 / 安装」两节改写：给出**包安装**（推荐）与 install.ps1（离线/无 pnpm）两条路。

**刻意不做的事**：bundle 补丁里**不**关 `plugin-package-inventory-deepseek`。
0.1.7-rc.2 一代宿主上该扩展与折叠互斥，但 bundle 补丁无法探测该扩展是否存在，
对不存在的 id 做 config 覆盖不安全；那一代由 install.ps1 按探测结果处理（原逻辑保留）。
