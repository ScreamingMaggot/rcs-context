RCS 0.1.24 改进与保留项
================================================================================
插件版本：toolfold（[T]/[V] 行式格式生成器）修复；contextinjector 仍为 v1.10.29
上一版：0.1.23（漂移 #11：折叠丢工具痕迹 + 覆盖守卫）
回退点：rcs-0.1.24 → rcs-0.1.23 → rcs-0.1.22 → … → rcs-0.1.8

本版主题：**行式日志的单行契约**——escVal 漏转 \r 会让一行撑成多行


--------------------------------------------------------------------------------
一、怎么发现的
--------------------------------------------------------------------------------
0.1.23 发布后，为事故会话 5fe3512e 重建被漂移 #11 写坏的 118 行 [T]（按源重放、调用真实
foldOne）。覆写后自检发现：逻辑行 218，但物理行 642 —— 有 424 条"无标记续行"。

定位：这些续行都以可见的 `\n` 两字符开头，说明**上一行里混进了裸 CR**。
追到 toolfold.mjs 的 escVal：

    const special = /[|\\"\n]/.test(s)                       // ← 不认 \r
    … .replace(/\n/g, '\\n')                                  // ← 只转 \n

Windows 工具正文普遍是 `\r\n`。`\n` 被转成两字符，`\r` 却**原样留下**。写进行式日志后，
裸 CR 本身被当作换行 ⇒ 一行撑成多行 ⇒ 面板 parseTranscript 与任何按行解析的下游
读到垃圾续行。

原事故日志里没暴露它，纯属侥幸：漂移 #11 让 action='?' 走了 fallbackRule，
**根本没生成 cmd= / head= / tail= 这些携带正文的字段**。也就是说这两个 bug 互相遮蔽——
形状漂移把格式缺陷藏住了，修好前者才让后者现形。


--------------------------------------------------------------------------------
二、改了什么
--------------------------------------------------------------------------------
escVal：`special` 判定加入 `\r`，并补 `.replace(/\r/g, '\\r')`。
现在 foldOne 的每条 [T]/[V] 保证是**单行**，不含裸 CR/LF。


--------------------------------------------------------------------------------
三、验收
--------------------------------------------------------------------------------
新增 tests/toolfold-single-line.test.mjs：对 pwsh / read / edit / grep / 未知工具五类输入
（正文一律含 \r\n）断言「输出全为单行、行首标记正确、竖线不破坏字段数」，并断言 CR 被转成
可见的 \r 字面量。

    修复后： ALL PASS
    反证：   把 escVal 退回修复前，同一输入 → 「旧版输出含裸 CR: true」
            JSON 形态 "[T] shell|pwsh|-|OK|P2|cmd=\"a\r\\nb\"|…"（\r 为真回车，\\n 为转义两字符）
            ⇒ 该测试确实能抓住这个缺陷，不是走过场。

重建事故日志后的完整性自检：物理行 218 = 逻辑行 218、无标记续行 0、问号行 0、
[T] 118 行（域分布 fs 54 / shell 46 / web 11 / jobs 4 / todo 2 / fs-search 1）、
其中 66 行带真实目标路径，另新增 11 行 [V] 数值锚点。
行尾与原文件一致（宿主侧本就写 CRLF，未改动）。


--------------------------------------------------------------------------------
四、保留项
--------------------------------------------------------------------------------
1. 只增日志的"一行一事件"是**隐式契约**，此前没有任何测试守着它。本版补上，
   但只覆盖 foldOne 出口；LOGcompiler 的 row() 仍不做防御性过滤（它信任上游）。
   是否要在 row() 处再加一道"含换行即拒写并记账"，等下一次真机数据再定，不凭空加。
2. toolfold 的 grade 语义（P1/P2）与 out_n 计数不在本版改动范围内。
