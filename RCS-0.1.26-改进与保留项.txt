RCS 0.1.26 改进与保留项
================================================================================
插件版本：CONTEXTinjector v1.10.30（新增"当前轮保护"）；其余组件同 0.1.25
上一版：0.1.25（目录重构 / 可安装插件包）
回退点：rcs-0.1.26 → rcs-0.1.25 → … → rcs-0.1.8

本版主题：**折叠不得吃掉"仍在飞的那一轮"**——修一条会导致主对话重复回答的缺陷


--------------------------------------------------------------------------------
一、症状（用户报告）
--------------------------------------------------------------------------------
思考强度 off（即启用外置推理）的会话里，**在压缩未完成时发送用户消息**，
预期是"等压缩完成 → 外置推理 → 主对话"，实际主对话**对同一条消息回复了两次**。


--------------------------------------------------------------------------------
二、真机证据（session-de4959d2-2544-4311-a5d4-8fb8b0d510d5，回合 2）
--------------------------------------------------------------------------------
    seq247  15:47:07  user/message  src=user           "怎么样你觉得好玩吗"
    seq251  15:47:10  assistant/message                "好玩。而且我觉得这一轮…"      ← 第一次回答
    seq254  15:47:21  user/message  src=plugin:CONTEXTinjector
                      surfaceOp = replace 247..251
                      sourceEventSeqs = [247, 248, 251]
                      ⇒ 转录 11 行，含 [ROUND] 2 / [U] 怎么样你觉得好玩吗 / [A] 校尺子得两半…
    seq255  15:47:21  step/start   turn=2 step=2
    seq259  15:47:24  assistant/message                "好玩。不是客套。……"           ← 第二次回答同一条
    seq261  15:47:24  turn/end

即：折叠把**本轮的 user 消息与刚产出的助手回复**一起替换成了一条 **user 角色**的转录，
表面尾部因此变成"用户发了话、没人回答"的形态 ⇒ 宿主再跑一步 ⇒ 重复回答。


--------------------------------------------------------------------------------
三、根因：折叠缺"当前轮保护"（设计缺口，非 0.2 漂移）
--------------------------------------------------------------------------------
`closedPrefixEnd` 在"所有 tool-call 都配到 result"时返回**表面末端**（allClosed ⇒ end = 最后一条）。
于是当 pre-step 折发生在**本轮第 2 步**（本轮首个工具已闭合）时，遮蔽集自然覆盖到本轮末尾。

代码里没有任何"进行中内容不进遮蔽集"的判据——而设计文档里那句话是有的：
"只折叠**已经彻底结束**的内容"。这条纪律此前靠 closed-prefix 的偶然性满足，本版把它变成显式守卫。


--------------------------------------------------------------------------------
四、修法
--------------------------------------------------------------------------------
新增纯函数 `openRoundClampEnd(entries, session, end)`（可单测）：

  1. 从端部向前找**最后一个真人轮起点**（role=user 且 classifyMessageSource ⇒ 'user'；
     自身转录节点 plugin:CONTEXTinjector 不被误认）；
  2. 若该起点之后存在 `turn/end` ⇒ 该轮已结束 ⇒ **不钳制**（轮末折主路径不受影响）；
  3. 若不存在 ⇒ 该轮仍在飞 ⇒ 遮蔽终点钳到该起点之前；钳成 <0 时本轮不折（reason=open-round）；
  4. 事件不可得或任何异常 ⇒ **不钳制**，退回旧行为（避免因查询失败让折叠永久停摆）。

判据与既有 `collectDeadCalls` 的"该轮是否已结束（其后有 turn/end）"同源，不引入新语义。

真机复核（同一会话五笔折叠，用守卫重判）：

    折叠 seq244  替换 10..11    轮起点 seq 10   该轮已结束 ⇒ 不钳制 ✔（合法折叠不受影响）
    折叠 seq245  替换 13..236   轮起点 seq 10   该轮已结束 ⇒ 不钳制 ✔
    折叠 seq254  替换 247..251  轮起点 seq 247  **仍在飞**  ⇒ 钳制  ✔（就是重复回答那一笔）
    折叠 seq262  替换 259..259  轮起点 seq 247  该轮已结束 ⇒ 不钳制 ✔
    折叠 seq275  替换 268..272  轮起点 seq 268  **仍在飞**  ⇒ 钳制  ✔（回合 3 的同类问题）

即：守卫精确命中两笔病灶，放行三笔合法折叠。


--------------------------------------------------------------------------------
五、验收
--------------------------------------------------------------------------------
· 新增 tests/round-guard.test.mjs：7 条断言（仍在飞→钳制 / 已结束→不钳制 / 无轮起点→不钳制 /
  自身节点不误认 / 轮起点在 0 → 延后 / 事件不可得 → 回退 / end<0 原样返回），全绿。
  ⚠ 夹具要点：宿主 `ownEvents()` 返回的是**按 seq 索引**的数组（`evs[seq]`），
    测试里必须造密数组，不能按位置堆放——这是本版写测试时先踩到、后修正的一个错。
· console 埋点：钳制发生时打印 `fold-clamped-to-open-round`，便于日后核查。
· 三份副本（安装位 / 仓库 / 交付包）同步，`node --check` 通过。
· EXTREASON pilot（176 局）在本缺陷上的暴露：折叠在 pilot 里只发生过 1 次（T1/off，23 行），
  该局是否受影响需按同一判据复核——若受影响，只影响那一局的机制读数，不涉及 T5/T6/T7 的裁决统计。
